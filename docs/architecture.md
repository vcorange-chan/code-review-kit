# 分析、解释与渲染的边界

当前注册 Rust、Python、Dart 适配器；--language auto 支持混合业务。Zig、C、Go 仍是未来范围。其他语言的显式源码范围可以作为上下文引用，不宣称已实现其调用分析。实际提取范围和限制见 [语言说明](languages.md)。

## 共享数据流

CLI / Pi / Cowork → 语言适配器 → 事实与证据摘要 → 独立解释 JSON → 固定 HTML 模板。

- `languages.py`：适配器注册及 `LanguageAdapter` 契约。
- `rust.py` / `rust_context.py`：Rust 的语法、可见上下文、类型线索、候选调用和相关类型。其他层不复制 Rust 规则。
- `python.py`：标准库 AST 提取与 Python 词法作用域、导入别名、方法接收者候选；不导入或执行目标源码。
- `dart.py`：复用固定版本 ast-grep，提取 Dart 方法、构造器、箭头函数及异常分支；不安装 SDK。
- `syntax_support.py`：适配器共用的事实记录和候选结果格式；语法规则仍留在各适配器。
- `indexer.py`：按文件缓存提取结果，隔离仓库、源语言选择与适配器版本；事实保留实际语言。
- `engine.py`：有范围限制的图遍历、调用状态、证据包与解释绑定。
- `business.py`：多来源业务视图和成功/降级返回边；优先使用符号锚点。
- `card_render.py`：输入、步骤、输出、分支和源码区域的小型渲染函数。
- `source_links.py`：默认嵌入源码与真实行号定位；显式外部链接策略。
- `render.py`：页面组装和证据索引；`reviewkit/templates/` 是唯一样式源。

新增语言实现 `parse / resolve_call / related_types`，输出共享字段并注册适配器。符号、范围、调用状态与来源证据属于共同协议；某种语言的语法和解析策略留在适配器内。第一版不预建尚未使用的语言实现。

自动路由仅按已注册后缀分派；混合索引查找调用候选时按调用者语言过滤。跨语言成功/降级边属于清单声明，不属于自动语法调用图。CLI、Pi、Cowork 共用入口、缓存、解释格式和固定模板。

## 调用状态

每个语法调用都保留一条边。它可能是唯一候选、多个候选或未解析。Rust 可从 `self` 和直接参数类型注解推断候选；对变量遮蔽、泛型、动态接收者、复杂表达式及无法确认的限定类型保留未解析原因。不声称完成类型检查。

未解析项按调用者、名称和原因分组显示，避免把同一调用的每个出现位置都展开成一大段。事实保留全部位置，模型默认只读有预算的证据包，不必追查所有标准库/外部调用。

## 摘要与过期

函数正文、可见导入、相关的函数/impl/module 属性、实际使用的本地宏、已纳入的候选下游与相关类型构成证据。无关类型的 derive 不再使整个文件的函数解释过期。相关类型、当前函数属性和可见导入仍保守跟踪；这不是完备的数据流分析。

业务锚点的 `symbol` 是稳定身份，行号由索引计算。可选 `offset/end_offset` 表示相对符号起点的片段；函数内部编辑仍需复核。旧行号引用继续可读，但明确提示其脆弱性。`pin-sources` 生成新清单，不自动更新解释摘要。

## 报告与分享

默认 HTML 内嵌所选源码快照，用页面内真实行号锚点定位，并复制仓库相对位置。报告生成过程不再注入本机绝对路径；源码文本本身可能包含用户写入的路径，分享前仍应查看实际内容。

`--link-mode relative` 要求源码目录结构一起保留；`local` 显式使用本机文件。`--link-template` 支持远程源码和编辑器 URL。链接策略属于渲染层，与语言无关。
